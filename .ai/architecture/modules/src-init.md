## Overview

- `scan.rs` builds the inventory from `git ls-files`: languages, manifests (npm, Cargo, pyproject, go, Nx `project.json`, moon `moon.yml`), stack/tooling labels, modules (declared projects, inferred dirs, big modules split into areas), dependency edges (manifest deps, moon `dependsOn`, tsconfig aliases, relative/package imports), ADR dirs and agent rule files.
- `history.rs` scores commits with `signals.rs` and diffs manifests to spot dependency swaps; candidates are clustered per module.
- `render.rs` writes config, overview and module docs; generated facts live between `kontext:facts` markers so reruns never clobber what agents or people wrote.
- `deepen.rs` plans tasks from the files themselves (`deepened`, `deepened_fingerprint`, decision `commits`), renders them for agents or inlines sources for `--deepen --llm`, and applies submissions.
- Pitfall: descriptions come only from README intros — AGENTS.md/CLAUDE.md are rules, and generator boilerplate is filtered (`util::is_boilerplate`).
