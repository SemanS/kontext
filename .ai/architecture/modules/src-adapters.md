## Overview

- `drivers.rs`: `McpDriver` (lazy child/HTTP session, argument auto-binding from the tool's input schema), `HttpDriver` (ureq, templated path/query/body/headers), `CommandDriver` (argv without a shell, stdin, optional output file, timeout).
- `mcp_client.rs`: newline-delimited JSON-RPC client; answers server-initiated `ping` and `roots/list` (with the repo root); streamable HTTP with session ids and SSE.
- `mod.rs`: `Registry::build` renders vars, evaluates `when` (command, file, repo regex, env, templated `exists`), creates drivers; `Adapter` maps payloads to `Hit`s (`items`, `split`, `where` filters, `map` with paths, `a|b`, `re:`, `tpl:` and `=literal`), serves `read` for owned URI prefixes, delivers events and exposes tools.
- A failing adapter trips a 30 s breaker instead of slowing every call; fan-out calls run in threads with a deadline.
- Pitfalls: template values that are exactly one `{{expr}}` keep their JSON type and `null`s are dropped — optional parameters simply disappear; adapter URIs need a scheme (`x://`) for `ctx_read` to route them.
