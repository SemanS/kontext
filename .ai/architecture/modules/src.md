## Overview

- `main.rs` calls the library's CLI in `cli.rs`; `lib.rs` keeps the engine modules private and exposes `application.rs` as the embedding facade. `mcp.rs` serves operations over stdio JSON-RPC, concurrently, reopening the repo context when config files change. `tools.rs` defines the agent tool surface shared by both.
- `api.rs` dispatches the versioned application contract for JSON CLI, structured MCP and library requests; `api_read.rs` owns configured-store queries, applicability, publication evidence and reviewed exports; `api_write.rs` owns extraction/formalization, draft history and recoverable idempotent staging. `KnowledgePolicy` gives verifying services the same committed configuration/parser/lifecycle rules without executing adapters or trusting caller-supplied parsed data.
- `app.rs` ties a discovered `Repo`, the layered `Config` (defaults → user → user-per-repo → shared `.ai/kontext.toml` → clone-local), the lazily built adapter `Registry` and the throttled index refresh together.
- `route.rs` decides which repository a path belongs to (this one, a submodule, another worktree or repository) for `dir` and for paths in focus, `ctx_why` and captures; `app::open_shared` keeps those other repositories' contexts.
- `store.rs` parses/writes entries in two styles (front matter, or classic ADR `**Status:**` fields) and renders `.ai/README.md`; `inbox.rs` keeps local candidates in the git common dir.
- `ops.rs` implements the behaviour; `hooks.rs` installs guarded hook blocks and runs pre-commit (validate + secret scan + staged index), prepare-commit-msg (trailers) and post-* (sync events).
- Invariants: Git holds shared knowledge; indexes, caches and snapshots are derived. Local inbox/history and operation receipts retain private workflow state and retry identity, so do not delete them during pending work. Repo-declared adapters never run without `kontext trust`; hooks never block on the network. Candidate ownership comes from Git's worktree registry, not derived path caches.
- Pitfall: `App::cfg()` is fixed per process — long-running code must go through `mcp.rs`'s reload or open a fresh `App` after writing config (init does).
